# Landing concept review

Review date: 2026-10-24. Three independent raster mockups generated with the built-in image tool. They are visual exploration, not implemented interfaces or accessibility certification.

## Shared product behavior

Use semantic document text and actions outside optional 3D. Every selected event exposes its source, explanation, uncertainty and next action. Claim state dimensions remain independent. The full application retains dedicated routes and a persistent claim workspace shell.

Canonical illustrative settlement: 100000 - 5000 - 10000 = 85000; synthetic 10% co-pay on 85000 = 8500; settlement = 76500 INR. Deduction order and base are illustrative assumptions, not universal policy rules.

## Visual inspection and corrections required

- Editorial journey concept: strong headline, whitespace and selected event. Remove unsupported 'in minutes' promise. Normalize the date mismatch to 12 versus 13 October; generated version shows 12 versus 14. Specify the co-pay base and distinguish payable settlement from confirmed payment destination.
- Evidence landscape concept: strong source comparison and visible uncertainty. Decouple the date-conflict edge from unrelated insurer-message/policy nodes so the graph does not imply unsupported causality. Replace arbitrary shortcut hints with an accessible documented control scheme. Restore a distinct final CTA in the full landing design.
- Atmospheric ribbon concept: clear visual distinction between narrative and evidence reading. Correct dates/stage labels: request on 14 October, document received on 16 October, review on 17 October. The generated 3D document and scrubber labels are not fully consistent. Use explicit text labels for icon controls.

All mockups abbreviate the full landing narrative. The selected implementation must deliberately include policy grounding, renewal uncertainty, evidence comparison, settlement, trust, consent/privacy and final action. Do not make deletion or privacy promises before those behaviors work.

## Accessibility and responsive implementation acceptance

- At 390px, text and primary actions precede artwork; replace wide graphs with an ordered source list and selected inspector. No horizontal document overflow at 200% zoom.
- All meaningful 3D selections have equivalent labeled HTML controls, logical focus order, visible focus and screen-reader feedback.
- Reduced motion disables ambient movement and scrubbing animation without hiding information. WebGL failure shows a static image plus complete text controls.
- Sample actual rendered contrast against WCAG AA once built; raster inspection cannot certify contrast, focus, keyboard behavior or touch targets.
- Validate coherent timeline changes, missing/contradictory evidence, extraction correction history, unknown regulatory applicability and settlement arithmetic with deterministic fixtures.

## Output dimensions

Prompts requested 1440px-wide layouts. The image service returned all three at 897 x 1752 pixels. Preserve originals without stretching or claiming native 1440px output. The selected frontend should implement a responsive 1440px desktop design and be visually checked at 390px, 768px and 1440px.

No implementation or live interaction has been claimed. No repository commit was made.
