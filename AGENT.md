# ClaimMe engineering handbook

ClaimMe explains Indian health-insurance claims with evidence. It never adjudicates, predicts approval, or turns review signals into accusations.

This phase is a frontend with synthetic data. Never collect actual identity, medical, financial or insurance documents. No live auth, upload, OCR, AI, insurer or grievance submission service is connected.

Architecture: Next.js App Router with shared domain types, deterministic functions and a versioned browser-backed demo repository. Preserve source references and uncertainty. Store monetary values in integer paise. Events and corrections append history. Never mutate earlier claim events. Keep policy clauses distinct from regulations and insurer decisions.

Use semantic HTML for essential information and controls. 3D is progressive enhancement with a complete equivalent list and static fallback. Reduced motion must preserve meaning. Global styles own tokens; shared components own reusable behavior. Lazy-load heavy visualization modules.

Run npm run check. Format with npm run format. Inspect the running frontend at desktop, tablet and mobile widths; verify core flows and compare with the selected visual. Record honest verification in design-qa.md.

Never commit .local-design/, AGENT.local.md, memory/, .env files, personal planning data, or real customer documents. Do not mention unrelated reference projects in tracked source/docs. Review staged files before committing. Do not use git add . blindly.
